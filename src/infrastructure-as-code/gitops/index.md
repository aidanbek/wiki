# GitOps

Подход к доставке, где **Git — единственный источник правды** о желаемом состоянии системы, а агент в кластере непрерывно
приводит реальное состояние к описанному в репозитории. Деплой = merge в Git, а не `kubectl apply` руками.

## Принципы

- Декларативное описание всего состояния хранится в Git (версии, ревью, история, откат через revert).
- **Pull-модель**: контроллер в кластере сам тянет изменения из репо и применяет — не CI пушит в кластер извне.
- **Continuous reconciliation**: агент постоянно сверяет факт с желаемым и устраняет drift (в т.ч. ручные правки).

## Инструменты

- **Argo CD**, **Flux** — реконсилируют состояние кластера Kubernetes из Git.
- Часто поверх [Helm](../helm/index.md)/Kustomize; секреты — через Sealed Secrets/SOPS/External Secrets.

## Плюсы и подводные камни

- Аудит и rollback «из коробки»: всё изменение — это коммит; откат — это revert.
- Меньше прав у CI: пушить в кластер не нужно, агент тянет сам — уже поверхность атаки.
- Подводные камни: drift при ручных правках (агент их затрёт), управление секретами в Git, рассинхрон при нескольких
  источниках изменений.
