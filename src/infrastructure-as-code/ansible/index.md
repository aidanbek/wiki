# Ansible

Инструмент конфигурации и оркестрации от Red Hat. Работает **без агента** — подключается по SSH и приводит хосты к
описанному состоянию. Силён там, где Terraform слаб: настройка уже существующих серверов, деплой, последовательные
операции.

## Модель

- **Playbook** (YAML) — список задач; **module** — атомарное действие (установить пакет, скопировать файл).
- **Inventory** — список хостов и групп; **roles** — переиспользуемые наборы задач.
- Большинство модулей **идемпотентны**: «пакет установлен», а не «выполни apt install» — повтор безопасен.
- Push-модель: управляющая машина инициирует подключение (агент на хостах не нужен).

## Provisioning vs configuration

- Terraform создаёт инфраструктуру (серверы, сети); Ansible настраивает то, что внутри (пакеты, конфиги, сервисы).
- Часто связка: Terraform поднял VM → Ansible настроил.

## Подводные камни

- Императивная природа: порядок задач важен, не каждый модуль действительно идемпотентен — проверяй `--check` (dry-run).
- Масштаб: push по SSH на тысячи хостов медленный — нужны forks/pull-режим/AWX.
- Для immutable-подхода (пересоздавать образ, а не править) лучше packer + базовые образы.
