# Terraform

Декларативный инструмент provisioning'а от HashiCorp. Описываешь желаемое состояние ресурсов на HCL, а Terraform через
провайдеров (AWS, GCP, K8s и сотни других) приводит реальную инфраструктуру к этому состоянию.

## Модель работы

- **State** — файл с текущим известным состоянием; по нему считается разница с конфигом.
- `plan` показывает, что будет создано/изменено/удалено; `apply` применяет; `destroy` сносит.
- **Providers** — плагины к API облаков; **modules** — переиспользуемые наборы ресурсов.
- Граф зависимостей определяет порядок и параллелизм создания.

## Практики

- **Remote state** (S3 + DynamoDB lock, Terraform Cloud) — общий state с блокировкой против гонок.
- Разделять окружения через workspaces/отдельные state-файлы; секреты — не в state в открытом виде.
- `plan` в PR, `apply` после ревью — инфраструктурный GitOps.

## Подводные камни

- **State — критичный и чувствительный артефакт**: содержит секреты, его потеря/рассинхрон ломает управление.
- **Drift**: ручные правки в консоли расходятся со state; лечит `refresh`/`import` и запрет ручных изменений.
- Удаление ресурса из конфига = его уничтожение при apply — внимательно читать plan.
- Альтернатива на знакомых языках — [Pulumi](../pulumi/index.md); OpenTofu — открытый форк Terraform.
