# Configuration Management

Управление конфигурацией приложения отдельно от кода: какие значения (URL БД, ключи, лимиты, тоглы) меняются между
окружениями и как доставлять их без пересборки. База — принцип 12-factor: конфиг в окружении, а не в коде.

## Зачем

- Один и тот же артефакт работает в dev/staging/prod, отличаясь только конфигом.
- Секреты не лежат в репозитории и не утекают в историю git.
- Часть настроек можно менять на лету, без редеплоя.

## Разделы

- [Environment Management](environment-management/index.md) — разделение конфига по окружениям (dev/staging/prod).
- [Config Servers](config-servers/index.md) — централизованное хранилище конфигов с hot reload.
- [Feature Flags](feature-flags/index.md) — runtime-тоглы для управления функциональностью без деплоя.

## Подводные камни

- Config drift — расхождение настроек между окружениями; держать единый источник.
- Управление секретами: шифрование, ротация, ограничение доступа.
- Документировать обязательные переменные — иначе деплой падает на missing config.
