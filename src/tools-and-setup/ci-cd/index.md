# CI/CD

Continuous Integration / Continuous Delivery — автоматизация сборки, тестирования и доставки кода. Каждый push
прогоняется через pipeline (сборка → тесты → деплой), что сокращает обратную связь и риск «больших» релизов.

## Ключевые понятия

- CI — частая интеграция изменений в общую ветку с автоматической проверкой (build + tests + lint).
- CD — автоматическая доставка прошедших проверку артефактов до staging/production.
- Pipeline — описанная в коде последовательность стадий (pipeline as code, обычно YAML в репозитории).
- Runner / agent — исполнитель джоб; shared (облачный) или self-hosted.

## Что обычно в pipeline

- Сборка артефакта/образа, кэширование зависимостей.
- Прогон тестов и статического анализа, security-сканы.
- Публикация в registry, деплой по окружениям с manual approval для prod.

## Разделы

- GitHub Actions — CI/CD внутри GitHub, экосистема готовых actions.
- GitLab CI — встроенный в GitLab pipeline через `.gitlab-ci.yml`.
- Jenkins — гибкий self-hosted сервер-ветеран с плагинами.

## Подводные камни

- Медленные/флакающие тесты обесценивают весь pipeline — следить за временем и стабильностью.
- Секреты только через хранилище CI, не в коде/логах.
- Один и тот же артефакт на всех стадиях (build once, deploy many) — не пересобирать под каждое окружение.
