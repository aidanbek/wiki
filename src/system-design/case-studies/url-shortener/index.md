# URL Shortener

Сервис коротких ссылок (как bit.ly): по длинному URL выдаёт короткий код, по коду редиректит обратно. Классический
read-heavy кейс с простой моделью данных, но интересным масштабированием чтения.

## Требования и масштаб

- Функционально: `POST /shorten` → код, `GET /{code}` → 301/302 редирект, опционально аналитика и TTL.
- Нагрузка резко асимметрична: чтений во много раз больше записей (read:write ≈ 100:1) — оптимизируем чтение.

## Генерация кода

- **Счётчик + base62** — монотонный id кодируется в `[a-zA-Z0-9]`; коротко, но предсказуемо (нужен распределённый
  генератор id, напр. диапазоны/Snowflake).
- **Хэш URL + усечение** — короче, но возможны коллизии → проверять и досаливать.
- Длина 7 символов base62 ≈ 3.5 трлн комбинаций.

## Хранение и чтение

- KV-хранилище `code → url` идеально под точечный доступ (см. [key-value](../../../databases/nosql/key-value/index.md)).
- Агрессивный [кэш](../../../fundamentals/caching/index.md) горячих ссылок + [CDN](../../../fundamentals/caching/system-level/cdn/index.md);
  80/20 — небольшая доля ссылок даёт основную долю переходов.

## Trade-off'ы

- 301 (постоянный) кэшируется браузером → меньше нагрузки, но теряется аналитика кликов; 302 — наоборот.
- Custom-алиасы требуют проверки уникальности; коллизии хэша требуют retry.
- Аналитику кликов выносят в асинхронный поток ([очередь](../../../infrastructure/message-queues/index.md)), чтобы не
  замедлять редирект.
