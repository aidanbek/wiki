# FinOps

Практика управления облачными затратами как инженерной задачей: сделать стоимость видимой, привязать её к командам и
оптимизировать без потери скорости. В облаке cost — это следствие архитектурных решений, поэтому им управляют инженеры, а
не только финансы.

## Принципы

- **Visibility** — теги/метки ресурсов, разбивка затрат по командам/сервисам, дашборды и алерты на аномалии.
- **Optimization** — right-sizing инстансов, удаление «зомби»-ресурсов, автоскейл вниз, выбор тарифа.
- **Accountability** — у затрат есть владелец; команды видят и отвечают за свой счёт.

## Рычаги экономии

- **Commitment**: reserved instances / savings plans для стабильной нагрузки (дешевле on-demand).
- **Spot / preemptible** для отказоустойчивых батчей — кратно дешевле, но могут отозвать.
- Storage tiers ([холодные уровни](../../infrastructure/storage/storage-tiers/index.md)) для редких данных.
- Контроль **egress** и кросс-региональной репликации — частая скрытая статья.

## Подводные камни

- Оптимизация в ущерб надёжности/скорости — ложная экономия; решает баланс, а не минимум счёта.
- Главные утечки незаметны: забытые ресурсы, переразмеренные инстансы, трафик между зонами.
- Без тегирования невозможно понять, кто и за что платит, — это фундамент FinOps.
