# Well-Architected

Набор рамок (frameworks) от облачных провайдеров с принципами «хорошей» архитектуры по нескольким измерениям. Не догма, а
чек-лист вопросов, по которым ревьюят дизайн системы в облаке.

## Столпы (pillars)

- **Operational Excellence** — наблюдаемость, автоматизация, runbooks (см.
  [operational-excellence](../../operational-excellence/index.md)).
- **Security** — least privilege, шифрование, защита по слоям (см. [security](../../security/index.md)).
- **Reliability** — отказоустойчивость, восстановление, мультизона (см.
  [resilience](../../infrastructure/resilience/index.md)).
- **Performance Efficiency** — правильный подбор ресурсов, масштабирование под нагрузку.
- **Cost Optimization** — платить только за нужное (см. [FinOps](../finops/index.md)).
- **Sustainability** — энергоэффективность и утилизация ресурсов.

## Как применять

- Периодический **well-architected review**: пройтись по столпам и зафиксировать риски и план.
- Использовать как общий язык для trade-off'ов: усиление одного столпа часто ослабляет другой (надёжность ↔ стоимость).

## Подводные камни

- Чек-лист не заменяет понимания требований — «галочки» без контекста дают переинженеренную и дорогую систему.
- Столпы конфликтуют; задача — осознанный баланс, а не максимизация каждого.
