Data Processing

Обработка больших объёмов данных: преобразование, агрегация, перенос между хранилищами. Ключевое различие — между
обработкой ограниченных наборов по расписанию (batch) и непрерывных потоков событий в реальном времени (stream).

## Разделы

- Batch-Processing — обработка ограниченных наборов данных пачками по расписанию.
- Stream-Processing — непрерывная обработка неограниченного потока событий в реальном времени.
- ETL-Pipelines — извлечение, преобразование и загрузка данных между источником и хранилищем.

## Batch vs Stream

- Batch: высокая пропускная способность, высокая latency допустима, данные ограничены и известны заранее.
- Stream: низкая latency (мс-секунды), данные бесконечны, нужна работа с состоянием и окнами.
- Многие системы комбинируют оба подхода (lambda/kappa-архитектуры).

## Сквозные требования

- Идемпотентность и обработка повторов: события приходят дважды и не по порядку.
- Контроль качества данных и наблюдаемость пайплайна (latency, доля ошибок) — иначе мусор тихо доезжает до витрин.
