Async Processing Patterns

Паттерны, которые делают асинхронную обработку надёжной. Сообщения теряются, дублируются и «протухают» — эти приёмы
описывают, как с этим жить, не теряя и не задваивая данные.

## Паттерны

- Idempotency — повторная обработка одного сообщения не меняет результат; обязательна при at-least-once доставке.
- Retry-Mechanisms — управляемые повторы с backoff и бюджетом, чтобы не устроить thundering herd.
- Dead-Letter-Queue — отстойник для сообщений, которые не удалось обработать после всех попыток.

## Как они связаны

- Доставка обычно at-least-once → нужна idempotency, чтобы повторы были безопасны.
- Повторы (retry) исчерпываются → сообщение уходит в dead-letter queue вместо бесконечного цикла.
- Вместе они дают предсказуемое поведение при сбоях: ничего не теряется молча и ничего не задваивается.
