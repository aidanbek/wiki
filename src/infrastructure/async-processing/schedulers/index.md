# Schedulers

Запуск задач по расписанию: периодические джобы, очистка, регулярные отчёты. По сути cron, но в распределённых системах
к нему добавляются HA, зависимости между задачами и алертинг.

## Как работает

- Расписание задаётся cron-выражением или интервалом.
- Простые варианты: системный cron, systemd timers. Сложные пайплайны: Airflow, Temporal.
- Распределённые шедулеры дают HA — нет единой точки отказа, задача не пропускается при падении узла.
- Зависимости между задачами выражаются через DAG; есть retry и алерты на падения.

## Когда использовать / подводные камни

- Use cases: batch-джобы, очистка устаревших данных, генерация отчётов, регулярная синхронизация.
- Задачи лучше делать идемпотентными — повторный запуск (после сбоя или дубля триггера) не должен ломать данные.
- На нескольких инстансах нужен лок/leader election, иначе одна задача запустится несколько раз.
