# Async Processing

Выполнение работы вне цикла запрос-ответ. Тяжёлые или медленные операции (отправка письма, генерация отчёта, обработка
видео) уходят в фон, а пользователь сразу получает ответ. Основа — очередь задач между producer'ом и воркерами.

## Зачем

- Снижает latency API: запрос не ждёт завершения долгой работы.
- Сглаживает пики нагрузки — задачи копятся в очереди и обрабатываются по мере сил.
- Изолирует сбои: падение воркера не роняет веб-слой, задача переобрабатывается позже.

## Разделы

- Task-Queues — очереди задач и воркеры (Celery, Sidekiq, Bull).
- Background-Jobs — долгие задачи вне запроса и хранение их результатов.
- Schedulers — запуск задач по расписанию (cron, systemd timers, Airflow).
- Patterns — паттерны надёжности: idempotency, retry, dead-letter queue.

## Подводные камни

- Доставка обычно at-least-once → обработчики должны быть идемпотентны (см. patterns/idempotency).
- Очередь нужно мониторить: длина, время обработки, доля ошибок — иначе отказ остаётся незамеченным.
- Нужен план для «ядовитых» сообщений, которые не получается обработать (см. dead-letter-queue).
