# Proxy (Forward & Reverse)

Посредник, через который проходит трафик. Различают по тому, чьи интересы он представляет: **forward proxy** действует от
имени клиента, **reverse proxy** — от имени сервера.

## Forward proxy

- Клиент шлёт запросы через прокси наружу; целевой сервер видит адрес прокси, а не клиента.
- Применение: корпоративный egress-контроль, фильтрация и логирование, кэширование, обход геоблокировок.

## Reverse proxy

- Стоит перед бэкендами; клиент думает, что общается с одним сервером.
- Применение: TLS-терминация, балансировка ([load-balancers](../load-balancers/index.md)), кэш (
  см. [reverse-proxy](../../../fundamentals/caching/system-level/reverse-proxy/index.md)), сжатие, WAF, единая точка входа.
- Примеры: Nginx, HAProxy, Envoy, Caddy.

## Подводные камни

- Прокси видит трафик в открытом виде после TLS-терминации — это новая точка доверия и атаки.
- Нужно аккуратно пробрасывать реальный IP клиента (`X-Forwarded-For`, `Forwarded`), иначе бэкенд видит адрес прокси.
- Лишний hop добавляет задержку и становится потенциальным single point of failure — нужна избыточность.
