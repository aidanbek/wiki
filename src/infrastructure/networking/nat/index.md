# NAT (Network Address Translation)

Подмена адресов в IP-пакетах на границе сети. Чаще всего множество приватных адресов скрывается за одним публичным —
это и продлило жизнь IPv4, и стало де-факто слоем изоляции.

## Виды

- **SNAT / Masquerade** — подмена источника: пакеты из приватной сети выходят с публичным IP роутера.
- **DNAT / Port forwarding** — подмена назначения: входящий трафик на порт публичного IP уходит на внутренний хост.
- **PAT (NAPT)** — много хостов за одним IP различаются по портам (домашние роутеры).

## Следствия

- Внутренние хосты по умолчанию недоступны извне — побочный эффект, не замена firewall.
- Состояние трансляций хранится в таблице соединений; долгие idle-соединения могут «протухать» (нужен keepalive).

## Подводные камни

- Ломает протоколы, передающие адреса внутри payload (SIP, FTP) — нужны ALG/хелперы.
- Усложняет peer-to-peer: для прямого соединения за NAT нужны STUN/TURN/ICE (WebRTC) или hole punching.
- CGNAT у провайдеров скрывает множество абонентов за одним IP — мешает геолокации и бан-листам.
- IPv6 устраняет необходимость в NAT для адресации, но изоляцию тогда обеспечивает уже firewall.
