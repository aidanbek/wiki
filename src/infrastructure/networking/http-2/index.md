# HTTP/2

Бинарная замена текстового HTTP/1.1 поверх того же TCP+TLS. Решает главную боль 1.1 — последовательную отправку запросов
в одном соединении — за счёт мультиплексирования множества потоков в одном подключении.

## Что нового

- **Бинарный фрейминг** — сообщение делится на фреймы (HEADERS, DATA), парсится машиной, а не построчно.
- **Мультиплексирование** — много параллельных streams в одном TCP-соединении, без блокировки очередью.
- **HPACK** — сжатие заголовков; повторяющиеся заголовки не шлются каждый раз заново.
- **Server Push** — сервер мог проактивно слать ресурсы (на практике почти не прижился, удалён в большинстве браузеров).
- **Приоритеты потоков** — клиент подсказывает важность ресурсов.

## Подводные камни

- **Head-of-line blocking на уровне TCP** остаётся: потеря одного пакета тормозит все streams соединения — это
  фундаментально лечит только [HTTP/3](../http-3/index.md) поверх QUIC.
- Один долгоживущий коннект меняет балансировку: меньше соединений, важнее distribution на L7.
- Выигрыш максимален на множестве мелких ресурсов; для одного большого файла разница с 1.1 невелика.
