# RabbitMQ

Многофункциональный брокер сообщений на протоколе AMQP. Сильная сторона — гибкая маршрутизация: producer публикует в
exchange, а тот по правилам раскладывает сообщения по очередям. Даёт больше контроля, чем SQS, ценой эксплуатации.

## Как работает

- Exchange маршрутизирует сообщения в очереди по типу: direct, topic, fanout, headers.
- Acknowledgments подтверждают обработку; без подтверждения сообщение возвращается в очередь.
- Поддерживает persistence, кластеризацию, приоритетные очереди, TTL сообщений.
- Плагины расширяют функциональность (например, отложенная доставка).

## Когда использовать / подводные камни

- Подходит, когда нужна сложная маршрутизация, приоритеты и тонкий контроль над доставкой.
- Больше операционных забот, чем у managed SQS: кластер надо разворачивать и обслуживать самому.
- Это очередь, а не лог: в отличие от Kafka, реплея «с начала» здесь нет — сообщение обработано и ушло.
