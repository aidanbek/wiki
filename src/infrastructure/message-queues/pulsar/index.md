# Apache Pulsar

Распределённая платформа обмена сообщениями, объединяющая модель очереди и лога событий. Ключевая особенность —
**разделение вычислений и хранения**: брокеры stateless, а данные лежат в Apache BookKeeper.

## Архитектура

- **Брокеры** обслуживают клиентов и не хранят данные → масштабируются и заменяются независимо.
- **BookKeeper (bookies)** хранит сегменты лога; репликация и durability на его уровне.
- Топик делится на сегменты, которые размазаны по bookie — нет «горячего» владельца партиции, проще ребаланс.

## Модель подписок

- Один топик, разные режимы подписки: **exclusive**, **failover**, **shared** (очередь, конкурентная обработка),
  **key_shared** (порядок по ключу + параллелизм).
- Это даёт и pub/sub, и очередь на одном топике — гибче, чем у [Kafka](../kafka/index.md).
- Встроенные: multi-tenancy, geo-replication, tiered storage (выгрузка старого в object storage), Pulsar Functions.

## Подводные камни

- Больше компонентов (брокеры + BookKeeper + ZooKeeper/метаданные) → сложнее эксплуатация, чем у NATS/RabbitMQ.
- Экосистема и зрелость инструментов уступают Kafka; выбирают ради мультиарендности, гео-репликации и гибких подписок.
