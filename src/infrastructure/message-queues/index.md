# Message Queues

Промежуточный слой для асинхронного обмена сообщениями между сервисами. Отправитель кладёт сообщение и не ждёт
получателя — это развязывает компоненты во времени, сглаживает пики и повышает устойчивость к сбоям.

## Разделы

- Kafka — распределённый лог событий для высоконагруженного стриминга.
- RabbitMQ — гибкий брокер с богатой маршрутизацией (AMQP).
- SQS — управляемая очередь в AWS, без обслуживания инфраструктуры.

## Зачем

- Decoupling: producer и consumer не знают друг о друге и не обязаны быть онлайн одновременно.
- Сглаживание нагрузки: сообщения буферизуются в очереди, consumer разбирает их в своём темпе.
- Устойчивость: если consumer временно лежит, сообщения дожидаются его, а не теряются.

## Как выбирать

- Нужен реплеи и высокий throughput событий, поток данных → Kafka (это лог, а не очередь в классике).
- Нужна сложная маршрутизация, приоритеты, гибкость → RabbitMQ.
- Вы в AWS и не хотите обслуживать брокер → SQS.
