# Object Storage

Хранилище с плоским пространством имён: нет дерева каталогов, каждый объект адресуется уникальным ключом. Объекты несут
богатые метаданные и доступны по HTTP (REST API). Масштабируется до петабайт — основа для бэкапов, статики и data lake.

## Как работает

- Плоское пространство имён: объект = данные + метаданные + уникальный ключ; «папки» — это лишь префиксы в ключе.
- Доступ по HTTP/REST; S3-совместимый API стал де-факто стандартом.
- Обычно eventual consistency и горизонтальное масштабирование до огромных объёмов.

## Когда использовать / подводные камни

- Use cases: статика и медиа, бэкапы, логи, data lake — всё, что много и неструктурированно.
- Дешевле блочного хранилища на масштабе и не несёт overhead файловой системы.
- Не файловая система: нет частичной записи в середину файла и привычных POSIX-операций — модель «положил/забрал объект
  целиком».
