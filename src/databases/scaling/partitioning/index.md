Partitioning

Разделение большой таблицы на меньшие части (partitions) в пределах одной БД. Упрощает работу с большими объёмами и
ускоряет запросы через отсечение лишнего.

## Стратегии

- Range: по диапазону значений (например, по дате) — удобно для time-series и архивирования.
- Hash: по хэшу ключа — равномерное распределение.
- List: по списку значений (регион, тип).

## Выгоды

- Partition pruning: запрос выполняется только на релевантных партициях.
- Упрощённое архивирование/удаление: DROP/DETACH партиции вместо массового DELETE; меньше/быстрее индексы на партицию.

## Нюансы

- Декларативное партиционирование в Postgres 10+; ключ партиционирования желательно в WHERE.
- Отличать от sharding: партиции в одной БД, шарды — на разных серверах (см. sharding).
