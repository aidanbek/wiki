# Database Scaling

Способы выдерживать рост объёма данных и нагрузки. Сначала масштабируют вертикально и за счёт реплик для чтений, и лишь
затем переходят к шардированию записи.

## Темы

- [Vertical](vertical/index.md) — больше ресурсов на одном сервере (просто, но есть потолок).
- [Horizontal](horizontal/index.md) — добавление узлов (линейный потолок, но распределённая сложность).
- [Replication](replication/index.md) — копии данных для масштабирования чтений и отказоустойчивости.
- [Load-Balancing](load-balancing/index.md) — распределение запросов по узлам/репликам.
- [Partitioning](partitioning/index.md) — деление таблицы на части в одной БД.
- [Sharding](sharding/index.md) — распределение данных по независимым серверам (масштабирует и запись).

## Порядок действий

- Оптимизация запросов/индексов → вертикаль → read-replicas → партиционирование → шардирование.
- Каждый следующий шаг дороже в эксплуатации — не торопиться к шардингу (см. cap-theorem, performance).
