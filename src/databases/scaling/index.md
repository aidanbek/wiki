Database Scaling

Способы выдерживать рост объёма данных и нагрузки. Сначала масштабируют вертикально и за счёт реплик для чтений, и лишь
затем переходят к шардированию записи.

## Темы

- Vertical — больше ресурсов на одном сервере (просто, но есть потолок).
- Horizontal — добавление узлов (линейный потолок, но распределённая сложность).
- Replication — копии данных для масштабирования чтений и отказоустойчивости.
- Load-Balancing — распределение запросов по узлам/репликам.
- Partitioning — деление таблицы на части в одной БД.
- Sharding — распределение данных по независимым серверам (масштабирует и запись).

## Порядок действий

- Оптимизация запросов/индексов → вертикаль → read-replicas → партиционирование → шардирование.
- Каждый следующий шаг дороже в эксплуатации — не торопиться к шардингу (см. cap-theorem, performance).
