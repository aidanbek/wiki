Document Databases

Хранение semi-structured данных в виде документов (JSON/BSON). Документ — самодостаточная единица с вложенными полями;
схема гибкая или валидируется опционально.

## Моделирование

- Embedding: вкладывать связанные данные в документ — быстрый чтение «всё за один запрос», но дублирование.
- Referencing: ссылки между документами (как foreign keys) — нормализация, но требует нескольких запросов/lookup.
- Выбор зависит от соотношения чтений/записей и того, читаются ли данные вместе.

## Свойства

- Schema-less гибкость или schema validation; индексы по вложенным полям; rich-запросы.
- Горизонтальное масштабирование через sharding; репликация для HA.

## Когда использовать

- Изменчивые/иерархичные структуры (профили, каталоги, контент), быстрые итерации схемы.
- Не идеально для сложных many-to-many и транзакций между сущностями (примеры: MongoDB, CouchDB).
