# N+1 Query Problem

Анти-паттерн: 1 запрос за списком сущностей + по 1 запросу за связанными данными каждой из N сущностей = N+1 запросов
вместо одного-двух. Классическая беда ORM с lazy loading.

## Симптомы

- В логах БД серия почти одинаковых запросов с разными id.
- Latency линейно растёт с размером списка; БД завалена мелкими запросами.

## Решения

- Eager loading: JOIN или подзапрос, чтобы притянуть связанные данные сразу (`with`/`include`/`JOIN FETCH`).
- Batch loading: один запрос `WHERE id IN (...)` (паттерн DataLoader в GraphQL).
- Кэширование связанных данных.

## Профилактика

- Включать логирование запросов в dev, ставить лимиты/детекторы N+1 в тестах.
- Понимать, когда ORM делает lazy load, и осознанно выбирать eager (см. [query-analysis](../query-optimization/query-analysis/index.md)).
