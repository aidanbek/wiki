Composite Indexes

Индекс по нескольким колонкам — для запросов с условиями сразу по нескольким полям. Эффективнее, чем отдельные
одноколоночные индексы, которые БД пришлось бы комбинировать.

## Leftmost prefix rule

- Индекс `(A, B, C)` работает для `A`, `A+B`, `A+B+C`, но не для `B`, `C` или `B+C` по отдельности.
- Поэтому порядок колонок критичен — ставить первыми те, что чаще в условиях равенства.

## Практики

- Колонки равенства — раньше, колонка диапазона/сортировки — последней.
- Можно сделать индекс covering, добавив колонки из SELECT (INCLUDE) — table lookup не нужен.

## Подводные камни

- Лишние/дублирующие составные индексы раздувают запись и storage.
- Проверять, что планировщик реально использует индекс (EXPLAIN), а не делает его scan впустую (см. index-strategies).
