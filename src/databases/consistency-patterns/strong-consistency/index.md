Strong Consistency

Все чтения видят последнюю подтверждённую запись немедленно — система ведёт себя так, будто данные в одной копии.
Linearizability — самая строгая форма (есть единый реальный порядок операций). Выбор CP в CAP.

## Свойства

- Требует координации между узлами → выше latency и риск недоступности при network partition.
- Реализуется через консенсус (Raft, Paxos), кворумы (R+W>N), distributed locks, single-leader запись.

## Когда использовать

- Банкинг, платежи, складские остатки, бронирование — где корректность важнее доступности.
- Уникальные ограничения, счётчики, операции, требующие read-modify-write без потерь.

## Trade-offs

- Дороже и медленнее eventual/causal; при partition часть системы становится недоступной.
- Не всегда нужна на весь датасет — часто достаточно strong для критичных сущностей, eventual для остального.
