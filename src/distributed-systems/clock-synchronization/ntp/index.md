NTP (Network Time Protocol)

Протокол, который подтягивает физические часы узла к реальному времени через сеть. Точность — порядка 1–50 мс в LAN,
десятки–сотни мс через интернет. Это «достаточно хорошо» для логов и мониторинга, но мало для строгой distributed
consistency.

## Как работает

- Иерархия серверов по уровням (strata): stratum 0 — эталон (атомные часы, GPS), stratum 1 — серверы, напрямую к нему
  подключённые, и т.д.
- Клиент измеряет round-trip и оценивает смещение своих часов относительно сервера.
- Алгоритм Marzullo отбраковывает «вруны» и выбирает согласованный интервал из нескольких источников.
- Коррекция обычно плавная (slewing), чтобы время не прыгало назад.

## Чего НЕ гарантирует

- Точного порядка событий между узлами — остаточный skew всё равно есть (см. [[logical-clock]], [[vector-clocks]]).
- Монотонности в граничных случаях — поэтому для измерения длительности используют monotonic clock, а не NTP-время.

## Когда достаточно

- Логирование, трейсинг, метрики, корреляция событий с погрешностью в миллисекунды.
- TTL и расписания, где небольшой разброс не критичен.
- Для строгой линеаризации нужны специализированные решения (PTP, TrueTime).
