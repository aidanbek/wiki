# Jaeger

Open-source бэкенд для distributed tracing, изначально созданный в Uber и принятый в CNCF. Собирает span'ы, хранит их и
даёт UI для разбора latency и зависимостей между сервисами (см. [[distributed-tracing]]).

## Архитектура

- **Agent/Collector** — принимают span'ы от приложений (нативно и через OpenTelemetry).
- **Storage** — бэкенд хранения: Cassandra, Elasticsearch, OpenSearch или память для разработки.
- **Query + UI** — поиск трейсов по сервису, операции, тегам и времени.
- Поддерживает adaptive sampling, чтобы балансировать полноту данных и нагрузку.

## Что даёт на практике

- Waterfall-диаграмма trace — сразу видно самый «дорогой» span.
- Граф сервисных зависимостей по реальному трафику.
- Поиск по тегам (например, по конкретному user id или ошибке).

## Когда выбирать

- Нужен зрелый, масштабируемый бэкенд под большой объём трейсов в Kubernetes-окружении.
- Инструментирование лучше делать через [[opentelmetry]], а Jaeger использовать как backend; альтернатива со схожей
  нишей — [[zipkin]].
