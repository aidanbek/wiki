Zipkin

Один из первых open-source трейсинг-бэкендов (вышел из Twitter, по мотивам Google Dapper). Проще и легковеснее [[jaeger]],
поэтому удобен для небольших систем и быстрого старта (см. [[distributed-tracing]]).

## Архитектура

- **Collector** — принимает span'ы (HTTP, Kafka и др.).
- **Storage** — in-memory, Cassandra, Elasticsearch или MySQL.
- **API + Web UI** — поиск трейсов и просмотр зависимостей.
- Может работать одним самодостаточным процессом — минимум операционных усилий.

## Сильные стороны

- Низкий порог входа: поднимается буквально одним контейнером.
- Совместимый формат span'ов, широкая поддержка в библиотеках.
- Достаточно функциональности для типичной отладки latency.

## Когда выбирать

- Небольшой или средний объём трейсов, важна простота развёртывания.
- При больших масштабах и более богатом анализе чаще берут [[jaeger]].
- Инструментировать код стоит через [[opentelmetry]], который умеет экспортировать в Zipkin.
