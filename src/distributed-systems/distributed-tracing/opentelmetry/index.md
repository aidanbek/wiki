# OpenTelemetry (OTel)

Вендор-нейтральный стандарт и набор SDK для сбора телеметрии: traces, metrics, logs. Решает проблему привязки к
конкретному вендору — вы инструментируете код один раз, а отправлять данные можно в любой бэкенд (
см. [distributed-tracing](../index.md)).

## Из чего состоит

- **API** — единый интерфейс для создания span'ов и метрик в коде.
- **SDK** — реализация API: сэмплирование, батчинг, обработка.
- **Collector** — отдельный сервис: принимает, обрабатывает (фильтрация, обогащение) и экспортирует телеметрию.
- **OTLP** — единый протокол передачи телеметрии между компонентами.

## Почему это важно

- Один стандарт инструментирования вместо проприетарных агентов под каждый вендор.
- Backend меняется без переписывания кода — достаточно сменить экспортёр в Collector.
- Контекст (trace id) пробрасывается между сервисами через W3C Trace Context.

## Связь с бэкендами

- OpenTelemetry **собирает** данные, но не визуализирует их — для этого нужен бэкенд.
- Трейсы экспортируются в [jaeger](../jaeger/index.md), [zipkin](../zipkin/index.md) или коммерческие системы; метрики — в Prometheus и аналоги.
