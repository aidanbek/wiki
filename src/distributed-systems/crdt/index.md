# CRDT (Conflict-free Replicated Data Types)

Структуры данных, которые реплики могут изменять независимо и без координации, а затем сходиться к одному состоянию
автоматически — без конфликтов и центрального арбитра. Основа offline-first приложений и многопользовательского
редактирования.

## Почему сходятся

- Операции слияния **коммутативны, ассоциативны и идемпотентны** — порядок и повторы доставки не влияют на итог.
- Дают **strong eventual consistency**: реплики, получившие один набор обновлений, гарантированно одинаковы.
- Два стиля: **state-based (CvRDT)** — шлют и мёржат состояние; **op-based (CmRDT)** — шлют операции (нужна надёжная
  доставка без дублей).

## Примеры типов

- G-Counter / PN-Counter — счётчики (только инкремент / инкремент-декремент).
- G-Set, OR-Set — множества (add-only / с удалением).
- LWW-Register — последняя запись по таймстемпу побеждает.
- RGA/Logoot и т.п. — последовательности для совместного текста (Yjs, Automerge).

## Подводные камни

- Платят памятью: метаданные (tombstones, версии) растут и требуют сборки/компакции.
- LWW теряет «проигравшую» запись — конфликт разрешается, но данные молча отбрасываются.
- Семантика слияния зашита в тип — не всякую бизнес-логику можно выразить как CRDT; иначе нужен консенсус.
