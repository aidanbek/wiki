# Quorum

Минимальное число узлов, которое должно подтвердить операцию, чтобы её считать выполненной. Кворумы — способ оставаться
консистентным и доступным, пока живо большинство, не дожидаясь всех.

## Кворумы чтения и записи

- Параметры: **N** — число реплик, **W** — кворум записи, **R** — кворум чтения.
- Если **W + R > N**, множества узлов для записи и чтения пересекаются — чтение увидит последнюю запись (strong-ish
  consistency). Это правило кворумного пересечения.
- Если **W + R ≤ N** — выше доступность и скорость, но возможны устаревшие чтения (eventual).
- Частые настройки: `W=R=(N/2)+1` (баланс), `W=N, R=1` (быстрое чтение), `W=1, R=N` (быстрая запись).

## Зачем большинство (N/2 + 1)

- Любые два большинства пересекаются хотя бы в одном узле — это не даёт системе «раздвоиться» при
  [split-brain](../split-brain/index.md).
- Поэтому кластеры делают **нечётными** (3, 5): 5 узлов переживают отказ 2, добавление 6-го не повышает отказоустойчивость.

## Подводные камни

- Кворума недостаточно для полной линеаризуемости — нужны read-repair, sloppy quorum/hinted handoff (Dynamo) меняют
  гарантии.
- При потере большинства система обязана отказать в записи, иначе теряет консистентность.
