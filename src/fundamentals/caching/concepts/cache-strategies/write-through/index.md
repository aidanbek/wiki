Write-Through

Запись синхронно в кэш и DB — успех только когда подтверждены оба.

## Как работает

- Каждый write идёт в оба места последовательно; кэш всегда актуален с DB.

## Trade-offs

- Сильная consistency, быстрые чтения (данные всегда в кэше), при падении кэша данные целы в DB.
- Высокая write latency (два записи) + cache pollution: пишем даже то, что не будут читать (ср. write-around).
