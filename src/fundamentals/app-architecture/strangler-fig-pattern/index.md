# Strangler Fig Pattern

Постепенная миграция от legacy-системы к новой путём инкрементальной замены — без рискованного big bang rewrite.
Название — от фикуса-душителя, обвивающего дерево.

## Как работает

1. Перед legacy ставят фасад/прокси, маршрутизирующий запросы.
2. Новая функциональность реализуется в новой системе, остальное идёт в legacy.
3. По мере готовности routing переключают на новое.
4. Legacy «удушается», пока не опустеет и его можно выключить.

## Плюсы

- Снижает риск, позволяет итеративную поставку и быстрый откат при проблемах.

## Условия

- Нужна продуманная декомпозиция и логика маршрутизации; синхронизация данных на переходный период.
- Применяется для перевода monolith → microservices и technology migration (см. microservices, databases/migrations).
