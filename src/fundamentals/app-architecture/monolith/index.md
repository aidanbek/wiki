# Monolith

Единое развёртываемое приложение, где все компоненты работают в одном процессе и адресном пространстве — традиционная
архитектура.

## Свойства

- Shared memory, in-process вызовы, единая кодовая база, обычно одна БД.
- Атомарный деплой (всё или ничего); масштабирование вертикальное или полной репликацией.

## Плюсы

- Простота разработки и отладки (всё в одном месте), естественные ACID-транзакции, низкая latency между частями.

## Минусы / когда перерастают

- При росте: tight coupling, долгий build, сложность координации больших команд, технологический lock-in.
- Репутация незаслуженно плохая — для малых/средних проектов часто оптимален; дисциплину даёт modular monolith (см.
  modular-monolith, microservices).
