# Microservices

Архитектура из множества небольших независимых сервисов; каждый владеет своим доменом и данными — это распределённая
система.

## Свойства

- Сервисы общаются по сети (REST, gRPC, messaging), независимо деплоятся, масштабируются и развиваются.
- Database per service — никакого общего хранилища.

## Плюсы

- Организационные: автономия команд, независимые релизы, технологическое разнообразие.
- Технические: точечное масштабирование, fault isolation, независимая эволюция.

## Цена

- Огромный overhead: распределённые транзакции (saga), сетевые задержки/отказы, observability (логи/трейсы/метрики),
  сложный деплой и отладка.
- Оправдан для крупных организаций с многими командами; overkill для стартапов — часто лучше начать с modular monolith (
  см. [modular-monolith](../modular-monolith/index.md), [service-mesh](../service-mesh/index.md), [fundamentals/app-architecture/ddd/bounded-contexts](../ddd/bounded-contexts/index.md)).
