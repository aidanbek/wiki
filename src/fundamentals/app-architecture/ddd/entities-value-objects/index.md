# Entities & Value Objects

Два базовых строительных блока тактического DDD, различающихся природой равенства и изменяемости.

## Entities

- Объекты с уникальной идентичностью, живущие во времени, изменяемые — определяются identity, а не атрибутами.
- `User` с `id=123` остаётся тем же, даже если имя/email изменились; equality by identity.
- Имеют lifecycle, хранятся обычно с primary key, содержат бизнес-логику и поддерживают инварианты.

## Value Objects

- Объекты без идентичности, определяемые атрибутами, immutable — описывают характеристики, а не «вещи».
- `Money(100, "USD")`, `Address(...)`, `DateRange(...)` равны, если равны все поля; безопасно шарятся.
- При изменении создаётся новый объект; инкапсулируют валидацию (`Money` не может быть отрицательным) и доменную
  логику (`Money.add()`).

## Зачем различать

- Value Objects делают модель богаче, выразительнее и type-safe — доменные понятия вместо примитивов (primitive
  obsession).
- Small, tested once, reused everywhere (см. [aggregates](../aggregates/index.md), [fundamentals/app-architecture/ddd](../index.md)).
