# Single Responsibility Principle (SRP)

Класс должен иметь одну причину для изменения — одну ответственность, одну ось изменений.

## Суть

- Если `User` содержит валидацию, persistence, бизнес-логику и отправку email — это четыре причины его менять.
- Разделяй: `UserValidator`, `UserRepository`, `UserService`, `NotificationService`.
- Не путать с «делает одну вещь»: класс может иметь много методов, если они служат одной цели.

## Как найти нарушение

- Критерий — кто инициирует изменение? Разные стейкхолдеры → разные ответственности → SRP нарушен.
- Симптом — God Object (см. solid/interface-segregation, grasp/high-cohesion).
