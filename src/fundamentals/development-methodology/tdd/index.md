# TDD (Test-Driven Development)

Разработка через тесты: сначала тест, потом код. Цикл Red-Green-Refactor.

## Цикл

1. Red — написать падающий тест на нужное поведение.
2. Green — минимальный код, чтобы тест прошёл.
3. Refactor — улучшить код, не ломая тесты.

## Плюсы

- Тесты как спецификация и живая документация; покрытие растёт органически.
- Принуждение к тестируемости улучшает дизайн (слабая связанность, явные зависимости).
- Меньше багов и страх рефакторинга снижается.

## Trade-offs

- Требует дисциплины, замедляет старт, плохо ложится на исследовательский/UI-код.
- Тесты на реализацию вместо поведения становятся хрупкими (см. [bdd](../bdd/index.md), [testing/unit-testing](../../../testing/unit-testing/index.md)).
