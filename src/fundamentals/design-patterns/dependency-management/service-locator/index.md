# Service Locator

Глобальный реестр сервисов с API для получения зависимостей: `var repo = ServiceLocator.Get<IRepository>()`.

## Идея

- Централизованная точка доступа, скрывающая создание и конфигурацию зависимостей.
- Класс сам «достаёт» зависимости из локатора, а не получает их через конструктор.

## Почему считается антипаттерном

- Скрытые зависимости — не видны в сигнатуре, сложно понять, что нужно классу.
- Затрудняет тестирование (надо подменять весь локатор), нарушает явность; по сути Singleton «на стероидах».

## Когда допустим

- Legacy-код или статические контексты, где полноценный DI невозможен (предпочтительнее DI/container) (см.
  dependency-injection, service-container).
