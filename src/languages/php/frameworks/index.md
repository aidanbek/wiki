# Frameworks

Фреймворки задают структуру приложения и закрывают типовые задачи веб-бэкенда: маршрутизацию, DI, ORM, валидацию,
очереди, аутентификацию. В PHP экосистема зрелая, с двумя доминирующими игроками и обилием готовых пакетов через Composer.

## Основные

- Laravel — «батарейки в комплекте»: Eloquent ORM, очереди, события, Blade, богатая экосистема (Horizon, Octane, Livewire).
  Быстрый старт, выразительный API; вес — за счёт «магии» фасадов и контейнера.
- Symfony — модульный и строгий: переиспользуемые компоненты (многие из них лежат в основе Laravel), гибкая
  конфигурация, упор на принципы и долгосрочную поддержку.
- Микрофреймворки (Slim, Lumen) — тонкий слой поверх роутинга/middleware для API и небольших сервисов.

## Что обычно даёт фреймворк

- Маршрутизация и middleware-пайплайн, DI-контейнер.
- ORM/Query Builder, миграции, валидация, формы.
- Очереди и фоновые задачи, события, кэш, локализация, аутентификация/авторизация.

## Как выбирать

- Продуктовая разработка с быстрой итерацией и большой командой — Laravel.
- Строгая архитектура, переиспользуемые компоненты, долгий энтерпрайс — Symfony.
- Лёгкий API-сервис без лишнего — микрофреймворк или standalone-компоненты Symfony/PSR.

## Подводные камни

- «Магия» (фасады, авто-резолвинг) ускоряет старт, но скрывает зависимости и усложняет тестирование.
- Привязка бизнес-логики к ORM/фреймворку затрудняет миграцию — выносить домен за слой инфраструктуры.
