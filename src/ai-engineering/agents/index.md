# Agents

LLM, которая не просто отвечает текстом, а в цикле **вызывает инструменты** (поиск, API, код, БД), наблюдает результат и
решает следующий шаг — пока не выполнит задачу. Модель становится «мозгом», управляющим действиями.

## Как устроено

- **Tool calling**: модели дают описание инструментов (имя, параметры, схема); она возвращает запрос на вызов, рантайм
  выполняет и возвращает результат.
- **Цикл**: думать → вызвать инструмент → получить результат → думать дальше (паттерн ReAct).
- **Память/состояние**: история шагов и промежуточные результаты держатся в контексте или внешнем сторе.
- Сложные сценарии — несколько специализированных агентов (multi-agent), оркеструемых между собой.

## Применение

- Ответы поверх внешних систем ([RAG](../rag/index.md) как один из инструментов), автоматизация многошаговых задач,
  ассистенты для кода.

## Подводные камни

- **Накопление ошибок**: ошибка на раннем шаге уводит весь цикл; нужны лимиты шагов и проверки.
- **Безопасность**: инструменты дают реальные действия — least privilege, подтверждение опасных операций, изоляция; вывод
  модели = недоверенный ввод (риск [prompt injection](../prompt-engineering/index.md)).
- Стоимость и латентность растут с числом шагов (каждый шаг — вызов модели); недетерминизм усложняет отладку.
- Чем проще решение (один промпт, фиксированный пайплайн), тем надёжнее — агент оправдан, когда шаги заранее неизвестны.
