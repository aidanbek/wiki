# Vector Databases

Хранилища, оптимизированные под поиск ближайших векторов ([embeddings](../embeddings/index.md)) по близости, а не по
точному совпадению. Дают быстрый семантический поиск на миллионах/миллиардах векторов.

## Как работают

- В основе — **ANN** (approximate nearest neighbor): жертвуют точностью ради скорости, т.к. точный поиск по всем векторам
  слишком дорог.
- Индексы: **HNSW** (граф, популярен), IVF, PQ (квантизация для экономии памяти).
- Метрики близости: cosine, dot product, L2.
- Часто поддерживают **гибридный поиск** (вектор + ключевые слова) и фильтры по метаданным.

## Варианты

- Специализированные: Qdrant, Milvus, Weaviate, Pinecone (managed).
- Расширения к существующим БД: **pgvector** (PostgreSQL), векторный поиск в Elasticsearch/OpenSearch, Redis.
- Для умеренных объёмов расширение к уже используемой БД часто проще отдельной системы.

## Подводные камни

- ANN — приближённый: параметры индекса задают trade-off recall ↔ скорость/память.
- Обновление/удаление векторов и пересборка индекса дороги; смена модели эмбеддингов = полная переиндексация.
- Не самостоятельная «память ИИ» — это поисковый слой; качество ответа определяет весь пайплайн RAG.
