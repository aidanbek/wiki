# Problem Details (RFC 9457)

Стандартный машиночитаемый формат ошибок HTTP API (RFC 9457, ранее 7807). Вместо того чтобы каждый сервис изобретал свою
структуру ошибки, есть общий JSON со `Content-Type: application/problem+json`.

## Поля

- `type` — URI, идентифицирующий тип проблемы (и ссылка на доку).
- `title` — короткое человекочитаемое название (не зависит от конкретного случая).
- `status` — HTTP-код (дублирует статус ответа, удобно при логировании).
- `detail` — подробности конкретно этого случая.
- `instance` — URI/идентификатор конкретного возникновения.
- Плюс произвольные **расширения** (напр. список невалидных полей).

## Зачем

- Единый формат → клиенты и инструменты парсят ошибки одинаково по всем сервисам.
- `type` как стабильный идентификатор позволяет программно реагировать, не парся строки `title`.

## Подводные камни

- Не утекать в `detail` внутренние данные (стек, SQL) — это потенциальная утечка для атакующего.
- `type` должен быть стабильным URI-идентификатором, а не меняющимся текстом.
- HTTP-статус всё равно нужен корректный — Problem Details дополняет его, а не заменяет.
