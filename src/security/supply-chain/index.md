# Supply Chain Security

Защита всего, что попадает в ваш продукт извне: зависимости, базовые образы, инструменты сборки, CI/CD. Большинство кода в
типовом проекте — чужой, и компрометация звена цепочки бьёт сразу по всем потребителям.

## Векторы

- **Уязвимые зависимости** — известные CVE в транзитивных пакетах.
- **Malicious packages** — typosquatting, dependency confusion (подмена внутреннего имени публичным), захват заброшенного
  пакета.
- **Компрометация сборки** — внедрение кода в CI/CD или артефакты (классика — SolarWinds, событие XZ).

## Контрмеры

- **Pin + lockfile** — фиксировать версии и хэши; ставить из lockfile, а не «latest».
- **SBOM** (CycloneDX/SPDX) — манифест всех компонентов; основа для аудита и реагирования на новые CVE.
- **SCA-сканеры** (Dependabot, Trivy, Snyk) и [vulnerability-scanning](../vulnerability-management/scanning/index.md) в CI.
- **Подпись и верификация** артефактов: Sigstore/cosign, SLSA-уровни, провенанс сборки.
- Приватный прокси-реестр и явный allowlist scope'ов против dependency confusion.

## Подводные камни

- Транзитивные зависимости — главная слепая зона; глубина дерева важнее прямых зависимостей.
- SBOM без процесса реагирования бесполезен — нужна автоматическая сверка с базами CVE и алерты.
- Минимальные базовые образы (distroless) сокращают поверхность и шум сканеров.
