# Mutation Testing

Тестирование самих тестов. Инструмент вносит мелкие изменения в код (**мутанты**) и проверяет, поймают ли их тесты. Если
после поломки кода тесты всё ещё зелёные — они ничего не проверяют по существу.

## Как работает

- Мутации: заменить `+` на `-`, `>` на `>=`, `true` на `false`, удалить вызов, вернуть `null`.
- Тест-сьют гоняют на каждом мутанте:
  - **killed** — хотя бы один тест упал (хорошо);
  - **survived** — все тесты прошли (плохо: дыра в проверках).
- Метрика — **mutation score** = убитые / всего мутантов. Куда честнее, чем line coverage.

## Зачем

- Покрытие показывает, что строка **выполнилась**, mutation — что её поведение реально **проверяется**.
- Подсвечивает тесты без ассертов и слабые проверки.

## Подводные камни

- Дорого по CPU: мутантов много, сьют гоняется многократно — запускают инкрементально (на diff) или ночью.
- **Эквивалентные мутанты** — изменения, не меняющие поведение; их нельзя убить, дают шум.
- Инструменты: PIT (Java), Stryker (JS/.NET), mutmut/cosmic-ray (Python), go-mutesting.
