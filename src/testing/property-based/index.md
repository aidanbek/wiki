# Property-Based Testing

Вместо примеров «вход → ожидаемый выход» формулируют **свойство**, которое должно выполняться для любого входа, а
фреймворк сам генерирует сотни случайных входов и ищет контрпример.

## Идея

- Описываешь инвариант, а не конкретные кейсы. Примеры свойств:
  - round-trip: `decode(encode(x)) == x`;
  - идемпотентность: `f(f(x)) == f(x)`;
  - согласованность с эталоном: своя быстрая реализация == наивной медленной.
- Фреймворк прогоняет свойство на множестве сгенерированных значений (включая крайние: 0, пустые, отрицательные, юникод).

## Shrinking

- Найдя падение, фреймворк **минимизирует** контрпример до простейшего (напр. `[5]` вместо списка из 200 чисел) — резко
  упрощает отладку.

## Подводные камни

- Сложно придумать хорошие свойства — это главный навык; плохое свойство = слабый тест.
- Недетерминизм: падение «иногда» → фиксируй seed для воспроизведения.
- Не замена примерных тестов: оба дополняют друг друга.
- Инструменты: QuickCheck (Haskell), Hypothesis (Python), fast-check (JS), jqwik (Java), gopter (Go).
